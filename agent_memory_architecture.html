Agent Memory Management Architecture

Captured on: 2026-04-05

Summary

Memory management for agents must be split into Memory Generation (Session vs. Lifetime) and Memory Retrieval. Because token limits exist, retrieval must use progressive disclosure, which requires Generation to write highly structured, hierarchical data.

1. Memory Generation

This phase is split into two scopes:

  • Session-level memory generation: Fast, transient, localized to the current task.
  • Lifetime memory generation: Persistent, curated, long-term knowledge.

Constraints & Triggers: Generation is bounded by several factors:

  • Context window limits: Determining what fits before compression is needed.
  • Update cadence (frequency): When do we trigger an update? (e.g., end of session, heartbeat, explicit user command).
  • Signal-to-Noise Ratio (SNR): Filtering out raw chat logs to keep only high-value insights.
  • User Intent Detection: Does the user want this remembered, or is it an implicit architectural learning?

2. Memory Retrieval

Retrieval must be highly structured due to token consumption and context length limits.

  • Progressive Disclosure: Retrieval should be hierarchical. Do not load the entire memory bank at once. Load high-level indices first, and progressively retrieve deeper layers only when the task demands it.
  • Dependency on Generation: For Progressive Disclosure to work during retrieval, the Memory Generation phase must write data in a highly structured format.

Vertical vs. General Purpose Application

  • Vertical-Specific (e.g., Coding): Applying this model to a specific vertical is tractable. The boundaries of what is "important" to generate and retrieve are well-defined.
  • General Purpose (e.g., OpenClaw): Applying this broadly across a general-purpose agent is significantly harder because the context and intent vary wildly across interactions.
